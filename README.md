# BunkrDL — Bunkr 相册下载工具

批量下载 Bunkr 相册：本工具直接下载，或者取得下载链接交给迅雷、IDM 等工具。设计见 [DESIGN.md](DESIGN.md)，状态与已知限制见 [STATUS.md](STATUS.md)，许可证 MIT（[LICENSE](LICENSE)）。

> 本工具不绕过人机验证，也不做代理池轮换；请遵守 Bunkr 的服务条款和所在地法律，只下载你有权获取的内容。

只需要 Python 3.11+ 和 `requests`。以下命令都在仓库根目录运行。

```bash
git clone https://github.com/BErrybearl/BunkrDL.git
cd BunkrDL
pip install requests
```

## 桌面窗口

```bash
python -m bunkrdl app
```

Windows 也可以双击仓库根目录的 `bunkr-app.pyw`（关联到 pythonw），无控制台打开窗口。要创建桌面入口，在仓库根目录手动运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\创建桌面快捷方式.ps1
# 指定其他 Python 环境时：
.\创建桌面快捷方式.ps1 -Pythonw "C:\Python313\pythonw.exe"
```

脚本在桌面创建或更新“Bunkr 下载.lnk”，重复执行不会新增副本，并自检目标路径。项目移动后请重新运行脚本。Python 环境必须装有本项目依赖。

桌面窗口另需 `pywebview`，缺少时运行 `pip install pywebview`。Windows 10 需要 Microsoft Edge WebView2 Runtime；若系统尚未安装，请安装微软提供的 WebView2 Evergreen Runtime 后再启动。

窗口默认使用本机端口 8765，被占用时依次使用下一个端口，实际端口显示在窗口标题。相同状态库只开一个桌面窗口；重复启动会尝试恢复已有窗口，无法唤起时显示中文提示。命令行正在持有任务锁或状态库无法打开时，窗口会直接说明原因。

关闭窗口时，没有处理或排队文件就直接退出；有任务时可选：

- **暂停后退出**：暂停全部，等待活动项收尾并停止服务，最长 20 秒；超时结束进程，保留的中断项在下次启动按现有规则恢复为排队并暂停，点“继续”接着处理。
- **继续下载（最小化到任务栏）**：保持服务运行，窗口最小化，可从任务栏恢复。
- **取消**：回到窗口。

## 网页

```bash
python -m bunkrdl web
```

浏览器打开 http://127.0.0.1:8765 。页面只有一页：

- **左栏**：粘贴相册链接后点“添加”。下面是相册列表，每个相册显示完成百分比、状态和失败数，点一下右侧就切到这个相册。相册的“更多”里可以打开文件夹、从列表移除（已下载的文件和记录都保留，重新添加就能恢复）。
- **右侧**：当前相册的文件表。
  1. 用上方的搜索框按文件名过滤，用筛选（全部、图片、视频、未完成、失败、链接已生成）缩小范围，点“名称/大小/状态”表头可以排序。然后勾选要处理的文件，或者用表头的全选，全选只选当前筛选出的文件。
  2. 选中后，操作栏里有：
     - **下载**：由本工具下载，图片、视频都可以。
     - **获取下载链接**：为选中的文件生成下载链接。每生成一条，文件表里就立刻显示“复制”按钮和剩余有效时间（**2 小时内有效**）。
     - **复制链接**：一次复制选中文件的全部链接，粘贴到迅雷、IDM 等工具里。链接已带原文件名。
     - **更多**：跳过（不计入完成百分比）、标为完成（用于检查外部下载文件夹后内容无法自动确认的文件）、改回待下载（已完成的文件也可以；只清空记录里的本地路径，磁盘文件不动，再下载时另存为 ` (2)`）。
     - **取消排队**：只有选中的文件还在排队（还没开始处理）时出现。取消后文件回到入队前的状态（待下载、失败或链接已生成；已经开始处理又被暂停的会停在待下载），其他文件不受影响，可以再次选中下载。正在处理的文件不能单独取消，等它结束或点顶栏“暂停全部”；文件表里正在处理的行不能勾选。

     文件表共六列：勾选、名称、类型、大小、进度、状态；进度列单独显示进度条和速度，状态列用一句话说明。排队中的行标“排队中”，正在处理的行标“处理中”，并各有底色。失败的行可以展开“查看完整错误”、复制错误，或点“重试本条”只重试这一个文件（始终按下载处理；链接已生成后又失败的文件，仍用上面的“重试失败的”按上次操作重试）。选中排队中的文件时，下载、获取下载链接、跳过、标为完成都会禁用并说明原因，避免点了才报错。
  3. 外部工具下完后，点“**检查外部下载文件夹**”。输入框默认收起，展开后标注“外部下载文件夹（仅用于检查，不是本相册的保存位置）”，选择或输入那个目录即可，界面不显示本相册自己的下载目录。下好的会改回原名并标为完成；没下完、下坏的、或大小对上但内容其实是错误页（HTML、JSON、报错文本）的标为失败，并且自动选好，直接点“下载”就由本工具补下。
  4. 有失败的文件时，会出现“重试失败的 (N)”，它会按每个文件上次的操作重试：上次是下载就重新下载，上次是生成下载链接就重新生成。命令行造成的失败也记住上次操作，同样按它重试。
- **顶栏**：常驻显示下载中、等待、失败的数量和总速度；进行中的文件最多显示 3 张卡片（文件名、通道、进度或阶段、速度），点一下就跳到对应相册，超出的显示“+N 个”。下面是图片和视频各自的并发设置、冷却状态和“暂停全部/继续”。冷却正常时显示“正常”，被限速时显示“冷却至 HH:MM（剩 N 秒）”和剩余时间条。
- **红色提示条**：某个文件失败时提示几秒，写明原因，例如“连接超时（可能是代理或网络问题）”，程序会接着处理下一个。连续 3 个文件失败、连续 4 次被限速，或者网站要求人机验证时，会暂停全部，原因一直显示在这里，可以点“继续”或“查看失败的”。

所有相册共用一个队列，按加入顺序处理。程序重启后，排队列表还在，处于暂停状态，点“继续”接着下；重启后仍显示上次的暂停原因和类型（例如连续失败、人机验证或连续限速），点“继续”后清除，只有没有保存过暂停状态时才显示“程序已重启，点‘继续’处理保留的文件”。

## 清除记录

状态库会一直累积相册和文件记录。要清掉它们，用网页上的两个入口：

- **左栏相册的“更多” → 清除这个相册的记录…**：删除这个相册的全部记录（相册本身、它的文件记录、排队项和这个相册的界面记忆），左栏随即不再显示它。
- **右侧“更多” → 清除选中的记录…**：只删除选中的文件记录。可以配合筛选使用：例如先筛“已完成”，用表头全选，再清除。

两者都只删状态库里的记录，**不会删除磁盘上已下载的文件**，也不会动外部下载文件夹里的任何东西。清除前会二次确认，写明要清除多少条记录、其中已完成多少个。清除时若相册里还有文件在排队或正在处理，会提示“还有文件在排队或处理，请先取消排队或暂停后再清除”：先取消排队或点“暂停全部”，等文件停下再清除。

“从列表移除”和“清除这个相册的记录”不是一回事：

| 操作 | 相册记录 | 文件记录 | 左栏 | 之后再添加同一相册 |
|---|---|---|---|---|
| 从列表移除 | 保留（标为隐藏） | 保留 | 不再显示 | 记录、下载目录和每个文件的状态都还在，接着用 |
| 清除这个相册的记录 | 删除 | 删除 | 不再显示 | 像全新相册：全部文件回到待下载，下载目录按 [DESIGN.md](DESIGN.md) 第 4 节的规则重新决定 |

磁盘上已有的文件不会因为清除而变动；重新添加后再下载时，按原有防覆盖规则处理，已有的同名文件不会被覆盖（另存为 ` (2)`）。

## 下载速度

| | 图片 | 视频 |
|---|---|---|
| 同时处理数 | 默认 2，可调 1–6 | 默认 1，可调 1–3 |
| 每个文件之后的等待 | 约 1 秒 | 2–4 秒 |

默认节奏是按真实相册调保守的：请求之间至少隔 0.7 秒，图片同时 2 个、视频 1 个。网站限制的是你的出口 IP，不是文件类型，所以收到限速（429）或服务器繁忙（503）时，**图片和视频一起停**：冷却期内不再开新文件，正在下的文件照常下完。冷却结束后先放 1 个文件试探，它下完才恢复到设置的并发。

冷却时长取服务器要求的等待时间（Retry-After）与退避值中较长的一个，退避按连续被限速的次数翻倍：120 秒、240 秒、480 秒，最长 900 秒；中间有一个文件成功就重新从 120 秒算。连续 4 次被限速会暂停全部，提示“被网站连续限速，已暂停。建议降低并发或等一会儿再继续”，可以点“继续”重试。被限速的文件不计入“连续 3 个文件失败”。冷却截止时间和连续次数都存在状态库，重启后仍然有效；重启后点“继续”不会跳过还没到期的冷却。顶栏冷却条正常时显示“正常”和两条通道的“设置 X · 当前限为 Y”，冷却时改显“冷却至 HH:MM（剩 N 秒）”。

Bunkr 没有公开并发限制；如果仍然经常被限速，就把同时处理数调低。

## 命令行

命令行一次只下一个文件，速度比网页慢，适合挂着跑或写脚本。

```bash
python -m bunkrdl get <相册链接>                     # 下载全部未完成的文件
python -m bunkrdl get <相册链接> --images            # 只下图片
python -m bunkrdl links <相册链接> --limit 10 --print  # 为 10 个视频生成下载链接并打印
python -m bunkrdl check <相册链接> <外部下载文件夹>      # 检查外部下载文件夹
python -m bunkrdl check <相册链接> <外部下载文件夹> --redownload  # 检查后由本工具补下
python -m bunkrdl handback <相册链接> <文件id...>    # 把指定文件改回待下载
```

`handback` 也能把已完成的文件改回待下载：只清空记录里的本地路径，磁盘文件不动，再次下载时另存为 ` (2)`。

按 Ctrl+C 暂停，再次运行同一命令从断点继续。高级命令 `add`、`list`、`download`、`export`、`reconcile`、`mark-done` 的用法见 `python -m bunkrdl <命令> --help`。

## 文件位置

| 内容 | 默认位置 |
|---|---|
| 下载目录 | `~/Downloads/bunkr/<相册标题> [<相册ID>]/`（v3 之前添加的相册，仅当原 `<相册标题>/` 目录存在、并有本相册的记录或 `.part` 归属指向它时才沿用；否则按新格式） |
| 命令行生成的链接文件 | 下载目录下的 `_export/<时间>/part-NN-links.txt` 等 |
| 状态库 | `~/.bunkrdl/state.db` |
| 请求日志 | `~/.bunkrdl/web.log`（1 MB × 3 轮转，只记主机、状态码、耗时） |
| 配置文件（可选） | `~/.bunkrdl/config.toml` |

数据目录可用环境变量 `BUNKRDL_HOME` 指定。旧版本把数据放在 `~/.workhub/bunkrdl/`：若 `~/.bunkrdl/` 不存在而旧目录存在，程序会继续使用旧目录（不移动、不改动其中文件）；想迁到新位置，关闭程序后把旧目录整体移动为 `~/.bunkrdl/` 即可。

配置文件只需写要改的项，键名见 [bunkrdl/config.py](bunkrdl/config.py)，例如：

```toml
download_root = "D:/Downloads/bunkr"
image_concurrency = 3
video_concurrency = 1
```

Bunkr 更换域名或接口时，改 `domains`、`api_url`、`sign_url` 即可。

## 出问题怎么查

1. **看红条文字**。单个文件失败时会提示几秒，写明原因和请求上下文，例如“被网站限速（429）· 阶段：文件体 · 主机 cdn.bunkr.cr · 建议等待 120 秒”。“阶段”说明卡在哪一步（相册页、解析、签名、文件体），“主机”说明是网站还是 CDN，同一句话就能判断该等还是该换网络。
2. **看请求日志**。`~/.bunkrdl/web.log` 每个请求一行：时间、阶段、方法、主机、状态码（或异常类型）、Retry-After、收到字节数、耗时；不含 token 和完整地址。1 MB 自动轮转，保留 3 份。如果 429 或超时集中在某个时间段，对照你使用的本地代理或网络工具的日志看同一时刻有没有限速或超时记录，就能分清是网站限的、还是代理/网络的问题。
3. **被限速后先等一会儿**。工具会自动停一会儿再继续，连续被限速就逐级加长：120 → 240 → 480 → 900 秒，中间有一个文件成功就回到 120 秒重新算。冷却期内点“添加”会直接提示还要等多少秒，不会白跑一次请求。
4. **还是太急就调低并发**。顶栏把图片、视频的同时处理数调小（图片 1–6、视频 1–3），新设置立即生效，正在下的文件不受影响。

## 遇到问题

- **一直显示连接超时**：多半是代理或网络的问题。工具通过系统代理访问 Bunkr，先确认代理软件在运行、能打开 bunkr.cr。
- **网站要求人机验证**：所有镜像都要求验证时，工具会暂停全部，不会尝试绕过。换个网络或过一阵再点“继续”。
- **一直被限速**：把顶栏的同时处理数调低。
- **命令行提示另一个任务正在运行**：网页正在下载时，命令行不能同时下载。等网页这边的任务停下，或在网页上点“暂停全部”。
- **外部工具下载时报 403**：说明它没有带上网站要求的来源信息。可以改用 Motrix 或 aria2，用命令行生成的 `part-01-aria2.txt` 导入。
- **下到的是维护占位视频**：工具会把它记为失败，不保存。等 Bunkr 的服务器恢复后点“重试失败的”。

## 分析请求日志

每个请求都记在状态库旁边的 `web.log`（默认 `~/.bunkrdl/web.log`，自动轮转，保留 4 个文件），可以汇总成中文报告：

```bash
python -m bunkrdl.logstat                  # 默认读 web.log 和 .1/.2/.3
python -m bunkrdl.logstat --since 2h       # 只看最近 2 小时，也接受 ISO 时间
python -m bunkrdl.logstat --json           # 机器可读
python -m bunkrdl.logstat D:/logs/web.log  # 指定路径，同样带上 .1/.2/.3
```

报告包括请求总数与时间范围、按阶段（解析/签名/文件体/相册页）和主机的分布、状态码、429 数量与占比、每次 429 前 10 秒的请求数（判断是并发还是请求率触发）、Retry-After 分布、每分钟请求速率、平均与最大耗时、超时的时间点，最后给一句调整建议。日志里不含链接、路径和令牌；格式不匹配的行只计数并忽略。
